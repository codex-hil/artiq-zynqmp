USER GOAL
A low-cost Sinara-like AWG: Kasli DRTIO -> scheduled RTIO parameters/profiles ->
local FPGA I/Q generator -> JESD204B -> AD9173-FMC-EBZ RevC, two RF outputs.
The user already owns AXAU15, AD9173 and a PCIe-to-SFP adapter. Its exact adapter
model/wiring is still unknown; establish whether it is a passive breakout or
an active PCIe NIC. Continue useful offline implementation while this is pending.
This is a parallel ALINX implementation. Do not interrupt the Trenz thread.

ARCHITECTURE
AXAU15 is Artix UltraScale+ XCAU15P-2FFVB676I, NOT a Zynq SoC and has no A53.
The user values fast local computation, but the budget variant cannot inherit
A53 kernel binaries. Start with a Kasli-controlled satellite and a softcore for
AUX/satellite management if needed. Keep local subkernel/PCIe-host computation
as explicit extensions, not as an already working feature. Reuse maintained
DRTIOSatellite/SyncRTIO/PhaserMTDDS design concepts; do not invent a custom
packet protocol where the upstream DRTIO interface is suitable.

IMPORTANT SOURCE DETAILS
- gateware/generate-link.py patches the ILAS HD bit to configuration octet10
  bit7 and computes the corresponding checksum. Preserve it.
- Drive DualLink converter_inputs, NOT core.sink directly: the latter was
  overwritten by the wrapper and transmitted zeros. Seven simulations and
  tools/check-old-wiring-regression.py cover this regression.
- Native GTHE4 8b10b: TXDATA32, TXCTRL2 charisk, TXCTRL0/1=0.
- Channel NCO0x130 bit6 must be enabled for interpolation>1, zero FTW for
  no channel shift; main NCO0x112 bit3 enabled for complex interpolation.
- Internal DC injection must be off when proving FPGA-sourced samples.
- Reference USER2 SPI console is stable-mailbox based. FMC SPI_EN is an INPUT,
  high impedance: the PIC owns that selector. Do not drive it.
- Reference slow-profile payload bit15 selects native PRBS7. This is a lab
  shortcut, NOT a valid arbitrary signed sample interface. Separate diagnostic
  PRBS control from waveform data before implementing arbitrary I/Q streams.
- reference/trenz_lab host scripts are historical and target Trenz explicitly.
  DO NOT RUN them against either board from this new thread. Refactor portable
  register operations separately from board/cable/runtime selection.

DRTIO OPTIONS
Prefer the user's passive PCIe-to-SFP breakout IF confirmed suitable. Use raw
GT DRTIO, not PCIe endpoint traffic. Trace real reference clock connectivity,
AC coupling, TX/RX direction and SFP control signals. Dedicated clock routing
must be legal; do not copy the experimental Trenz fabric GTGREFCLK route as a
production solution. Alternatively DRTIO-over-EEM/LVDS is supported upstream,
but existing eem_serdes uses 7-series primitives and needs an UltraScale+ port
and a suitable physical interface. A local source reference is
artiq/gateware/targets/phaser.py and drtio/transceiver/eem_serdes.py in the pinned
ARTIQ tree. Shared RTIO/DSP/JESD clocking and deterministic update epochs matter;
an asynchronous FIFO alone does not establish repeatable RF phase.

IMPLEMENTATION ORDER
1. Establish reproducible AXAU15 target: exact Vivado part, IO/GT pinmap,
   tool/license availability, clock/reset design. Compile and simulate offline.
2. Extract board-independent AD9173/HMC profile and SPI engine from reference.
   Add identity guards and board-specific cable/lease configuration.
3. Bring up dedicated-reference JESD, DAC IDs/PLL/DLL and both output tones.
   Verify payload amplitude/zero/recovery and a nonsymmetric sample word.
4. Implement programmable complex DDS/IQ source, first one oscillator per RF
   output; signed samples, phase, amplitude, mute and atomic parameter updates.
   Then extend to multiple tones/profiles with explicit headroom/saturation.
5. Connect upstream RTIO PHY to timestamped parameter/profile commits; keep the
   time-critical sample path in PL. Establish legal shared clocks and epoch.
6. DRTIO PHY/management and actual Kasli integration after adapter identification;
   test timestamped output changes, link loss/recovery and measured RF timing.
7. Optional waveform BRAM/DDR and PCIe host processing. Do not promise an A53
   equivalent or raw ADC feedback until interfaces and performance are measured.
